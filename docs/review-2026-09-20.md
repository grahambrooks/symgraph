# Project review — 2026-09-20

A functional and cross-functional review of symgraph at `1fd4991`, together with
the plan for working the findings off. Baseline at time of review:
`cargo clippy --all-features --all-targets -- -D warnings` clean, 186 tests green.

What is already good and should not be disturbed: `ops` as a presentation-neutral
layer shared by the CLI and the MCP server, `security::safe_join` as a real path
gate with symlink-escape coverage, the shadow-database rebuild with atomic swap,
constant-time bearer comparison plus the refusal to bind non-loopback without a
token, and only three `unwrap()`s outside tests.

The findings are grouped by theme. Each carries an ID so the plan and commit
messages can refer to it.

---

## 1. Functional — answers that are wrong or silently incomplete

### F1. Name-only symbol resolution picks an arbitrary definition

`db/mod.rs:457` — `find_node_by_name` is `SELECT * FROM nodes WHERE name = ?1
LIMIT 1` with no `ORDER BY`. `find_target_preferring_file` (`db/mod.rs:1332`)
prefers a same-file match and otherwise falls back to that arbitrary pick.

Every tool routes through it: `ops/mod.rs:119,193,294`, `graph/mod.rs:28,38,49,118`,
`blame.rs:14`, `db/mod.rs:1178`. In any codebase with a `new`, `build`, `handle`,
`run` or `get` per type, all call edges to that name are attributed to one
arbitrary definition. This is the root cause of over-reported module-graph cycles,
and it propagates into callers, callees, impact, coupling-score and god-struct.

Fixes, cheapest first:

- Deterministic `ORDER BY` so results stop changing between reindexes.
- Count candidates; when more than one, set `ambiguous` / `candidates` on the
  result so a caller knows the confidence.
- Use the `Imports` edges already extracted (with `detail`) to scope resolution
  to the imported module, then same-dir, then same-crate.
- Consider emitting edges to every candidate tagged `detail = "ambiguous"` rather
  than one wrong edge. Over-reporting is recoverable; silent misattribution is not.

No tool accepts a disambiguator either — `SymbolRequest` (`mcp/types.rs:27`) has
only `symbol`. It needs an optional `file` / `qualified_name`.

### F2. Results truncate silently

`ops/mod.rs:382-397` — callers and callees cap at `DEFAULT_GRAPH_LIMIT = 20` and
report `count: nodes.len()`. The JSON says `"count": 20` with no `truncated` flag
and no way to ask for more; a caller reading "Found 20 callers" concludes that is
all of them, which is exactly wrong for impact analysis. Same shape in
`graph/mod.rs:77` (`get_callers(node_id, 100)` hardcoded inside the BFS) and in
`MAX_REFERENCES_PER_KIND = 20`.

`references()` already distinguishes `count` from `shown`. Apply that shape
everywhere and add `limit` / `offset` to the request types.

### F3. `symgraph-context` ignores the semantic index

`context/mod.rs:140+` extracts keywords with a hand-rolled stop-word list and
calls `search_nodes` (prefix-only). `db.semantic_search` (`db/mod.rs:1301`) does
bm25 over camelCase-split identifiers plus docstrings — built for exactly this —
and is reachable only through `symgraph-search --semantic`. The flagship tool has
the weakest retrieval.

### F4. Tool-surface gaps against the parity design *(fixed)*

`docs/cli-mcp-parity.md` states `--format json` on every tool. It was missing on
`ContextRequest`, `SearchRequest`, `DiffImpactRequest`, `BlameRequest` and
`ChurnRequest`. `SearchRequest` also had no `limit` although `db.search_nodes`
takes one, so search was hard-capped at 10 results.

Each of the five gained a typed result in `ops` with a `Render` impl, so they
go through the same `present()` path as everything else rather than building
strings. `status` and `reindex` were given the same treatment while in there,
which takes it to **all 14 request types**. Blame output is parsed into
`{commit, author, date, line, text}` rather than shipped as one opaque string,
and churn and search results carry the standard `Page`.

### F5. Parse failures are invisible

`extraction/mod.rs:33` never checks `tree.root_node().has_error()`. A file that
fails to parse yields partial symbols and `stats.errors` stays 0. There is no
file-size cap either, so one minified bundle will consume the machine. Record a
per-file `parse_ok`, surface the error rate in `symgraph-status`, and skip files
over a configurable byte limit.

### F6. Windows path keys

`lib.rs` `collect_entries` stores `rel_path` from `path.strip_prefix(root).display()`,
so native separators. Only `coupling.rs:50` and `extraction/mod.rs:778,796`
normalise. On Windows the database is keyed `src\foo.rs` while every MCP client
passes `src/foo.rs`, so `symgraph-file` and targeted `symgraph-reindex` return
nothing. Normalise to `/` at the single insert choke point and in
`ops::format::normalize_path`.

### F7. `git log --name-only` and non-ASCII filenames

`churn.rs:36` — git quotes non-ASCII paths by default (`core.quotePath`), so churn
keys do not match database paths and volatility silently reads zero for those
files. Pass `-c core.quotePath=false`, or use `-z`.

### F8. `symgraph-implementations` had never worked *(fixed)*

Found while writing handler tests in commit 5. `Database::find_implementations`
queries `WHERE e.kind IN ('implements', 'extends')`, and extraction emitted
neither edge kind for **any** of the 13 languages, so the tool always answered
"No implementations found" — for a trait that plainly had an impl. It is
advertised in the README, the MCP tool list, the CLI command table and the
server instructions.

Fixed by teaching extraction to read inheritance clauses. Two mechanisms,
because the grammars split into two shapes:

- **Clause-based** (every language but Rust): a type declaration carries child
  nodes naming its supertypes. `LanguageConfig` gained `extends_clause_types`
  and `implements_clause_types`, filled per language from the grammars' actual
  node kinds — `superclass`/`super_interfaces` (Java, Groovy),
  `extends_clause`/`implements_clause` and `extends_type_clause` (TypeScript),
  `class_heritage` (JavaScript), `argument_list` (Python),
  `base_class_clause` (C++), `base_list` (C#), `delegation_specifiers`
  (Kotlin), `extends_clause` (Scala), `superclass` (Ruby). The scan recurses
  through the declaration's non-body children, so wrappers need no special
  case and a class body is never mistaken for a base list.
- **Rust**: inheritance lives on a sibling `impl Trait for Type`, not on the
  declaration, so it is matched back to the type declared in the same file.
  An inherent `impl Type` emits nothing.

Go is deliberately left empty: embedding is structural and interface
satisfaction is implicit, so there is nothing in the syntax to record.

`EXTRACTOR_VERSION` went to 2, so indexes built before this read as stale and
rebuild rather than continuing to answer "none found" — the first real use of
commit 3's provenance mechanism.

On symgraph's own codebase this produces 9 `implements` edges, and
`symgraph-implementations Render` now returns the nine `ops` result types.
Covered by one extraction test per language, since the clause shapes differ
enough that a grammar update could move any one of them independently.

## 2. Concurrency and reliability

### C1. `is_reindexing` is per-session, so the guard does not work over HTTP

`server.rs:95` constructs a handler per session through `SymgraphHandler::new_shared`,
and `mcp/mod.rs:109` gives each one its own `Arc::new(AtomicBool::new(false))`.
The database is shared; the flag is not. Two HTTP sessions can each start a full
rebuild and contend for the write lock. The flag belongs next to the shared
`Arc<RwLock<SyncDatabase>>`.

### C2. Every tool call blocks a tokio worker thread

All `#[tool]` methods in `mcp/mod.rs` are synchronous and do blocking SQLite and
`git` work directly on the reactor. `symgraph-coupling-score` on a large repo, or
a `git blame` that stalls, freezes the server for every session. Handler bodies
should go through `tokio::task::spawn_blocking`, as reindex already does.

### C3. No timeouts on git subprocesses

`churn.rs:36`, `blame.rs:26`, `diff_impact.rs:139` and `db_utils.rs:120` all call
`Command::output()` with no timeout and no output cap. A hung git — credential
prompt, network filesystem, an enormous `--since` window, and `days` is an
unvalidated `u32` — hangs the call forever, and `handle_blame` holds the database
read lock while it does.

### C4. No `busy_timeout`

`CONNECTION_PRAGMAS` (`db/mod.rs:29`) sets `auto_vacuum`, `foreign_keys`, WAL,
`synchronous` and `cache_size`, but not `busy_timeout`. The CLI `index`, `watch`
and the MCP server can all open the same index, so the first contention returns
`SQLITE_BUSY` immediately instead of waiting.

### C5. `unsafe impl Sync` with `RwLock` is a latent footgun

`mcp/mod.rs:67` — the comment credits SQLite's serialized mode, but that protects
the C library, not the `RefCell` statement cache inside rusqlite's `Connection`.
Two concurrent read-lock holders calling `prepare_cached` is undefined behaviour.
Read paths currently use `prepare`, so it does not fire, but one `prepare_cached`
added to a read path turns it on. Cheapest correct fix is `Mutex` in place of
`RwLock` — the `unsafe impl` becomes sound and nothing is lost, since SQLite
serializes anyway. The proper fix is an `r2d2_sqlite` pool, which also buys real
read parallelism.

### C6. No schema or index versioning

`db/schema.rs` migrations are additive `ALTER TABLE`s matched on the string
`"duplicate column name"`. There is no `PRAGMA user_version` and no record of
which symgraph or extractor version built the index, so upgrading symgraph leaves
a stale index answering confidently with old semantics. An `index_meta` table
carrying schema and extractor versions, with auto-rebuild on mismatch, closes it.

## 3. Performance and scalability

| ID | Issue | Where | Effect |
|---|---|---|---|
| P1 | Whole source tree held in RAM | `lib.rs` `collect_entries` → `extract_entries` | `Vec<FileEntry>` holds every file's contents, then `Vec<ExtractedFile>` holds contents *and* all nodes and edges before any write. Peak memory is repo size plus graph. Stream in chunks. |
| P2 | Every file read and SHA256'd on every incremental run | `collect_entries` | `needs_reindex` is checked after the full read and hash. Short-circuit on `size` and `mtime` from the `files` table, hash only on mismatch. |
| P3 | `resolve_references` is N+1 | `db/mod.rs:647` | Per unresolved ref: two lookup queries, an `is_test` query and an insert. Dominates full-index time, and is expressible as one set-based `INSERT INTO edges … SELECT … JOIN`. |
| P4 | `get_edge_endpoints()` loads the entire edge table | `db/mod.rs:382`, used by `module_graph.rs:34` | An unfiltered three-way join into memory on every module-graph and coupling-score call. Aggregate in SQL by folded path instead. |
| P5 | "Reindex one file" walks the whole tree | `reindex.rs:47` | `index_codebase` re-walks and re-hashes everything after deleting the named files. |
| P6 | No benchmarks | — | The value proposition is speed on large repos and nothing guards against regression. A `criterion` bench over a synthetic tree would. |

## 4. Security and supply chain

- **S1. No checksum verification in `install.sh`.** `curl | bash` downloads a
  tarball and installs it with no SHA256 check, and the release workflow publishes
  no `SHA256SUMS`. Publish checksums, verify them in `install.sh` and `install.ps1`,
  and add `actions/attest-build-provenance`.
- **S2. The "universal" macOS bundle is not universal.** `release.yml` says
  "lipo only works on macOS, so we'll just include arm64 as primary" and ships an
  arm64-only binary named `darwin-universal`. An Intel Mac gets a binary it cannot
  run. Either run `lipo` on a macOS runner or drop the artifact.
- **S3. Shell-to-Python interpolation in `install.sh`.** `configure_json` splices
  `${file}` and `${SYMGRAPH_BIN}` — derived from `$SYMGRAPH_INSTALL_DIR` — straight
  into Python source. Pass them through `sys.argv`.
- **S4. MCP config target looks wrong.** `install.sh` writes `mcpServers` into
  `~/.claude/settings.json`; Claude Code reads MCP servers from `~/.claude.json`
  and `.mcp.json`. Needs verifying — `--mcp` may be a silent no-op for Claude Code.
- **S5. No `cargo audit` or `cargo deny` in CI**, no `rust-toolchain.toml`, and no
  `rust-version` in `Cargo.toml`. The README's "rust 1.70+" badge is almost
  certainly false given rmcp 2.1 and axum 0.8.
- **S6. Workflow permissions.** `release.yml` grants `contents: write` and
  `packages: write` at workflow scope to all five jobs; `build.yml` has no
  `permissions:` block at all. Scope per job, and pin actions by SHA.
- **S7.** `safe_join` allows non-existent paths through intermediate symlinks —
  canonicalize fails, the lexical check passes. Only matters if a handler ever
  writes, but it belongs in the doc comment.
- **S8.** `churn.rs` validates the path and then passes the raw string as a git
  pathspec. `:/…` magic resolves against the worktree top, which can be above
  `project_root`. Prefix with `--` and `:(literal)`.

## 5. Observability

- **O1. Errors are just strings.** `with_db` (`mcp/mod.rs:118`) returns
  `format!("Error: {}", e)` as a *successful* tool result, so MCP clients cannot
  distinguish failure from output. Return `Err` and set `isError`.
- **O2. Silent degradations with no logging.** `search_nodes` swallows every FTS
  error and falls back to LIKE (`db/mod.rs:315`); `maybe_churn` swallows git
  failure and shows zeros throughout (`module_graph.rs:25`); `insert_edges_batch`
  and `insert_unresolved_refs_batch` silently drop unmappable rows. Each should at
  least `warn!`.
- **O3. No FTS integrity check.** `nodes_fts` is external-content but maintained by
  hand rather than by triggers. `symgraph-status` should run
  `INSERT INTO nodes_fts(nodes_fts) VALUES('integrity-check')`.
- **O4.** `symgraph-status` should report index age, schema and extractor version,
  unresolved-ref count and ambiguous-resolution count — the things that tell a user
  whether to trust an answer.

## 6. Testing and maintainability

- **M1.** 186 tests, but `src/ops/mod.rs` has none — that is the shared logic and
  rendering layer behind both front-ends. Also untested: `mcp/mod.rs`,
  `context/mod.rs`, `cli/commands.rs`, `cli/tools.rs`, and 14 of 18 handlers
  (`module_graph`, `god_struct`, `unused`, `path`, `hierarchy`, `implementations`,
  `diff_impact`, `dispatch_sites`, `churn`, `blame`, `file`, `search`, `status`).
  Snapshot tests over markdown and JSON output would be cheap, and would lock the
  CLI/MCP parity the design doc promises.
- **M2. Two overlapping CI workflows.** `build.yml` and `ci.yml` both run test,
  fmt and clippy on push and pull request — double the runner cost and two places
  to drift. `ci.yml` is the more complete one: it adds the CLI-only feature combo
  and Windows.
- **M3. `make release` is macOS-only** — `sed -i ''` is BSD syntax. And `make check`
  does not cover the CLI-only feature combo that CI gates on, so
  `make check && make release` can push a tag CI will reject.
- **M4.** The crates.io version gate runs after the GitHub release is published.
  The tag-versus-`Cargo.toml` check belongs in a pre-flight job.
- **M5. README is stale.** It lists eight languages; 14 grammars ship (add C#,
  Kotlin, Scala, Groovy, Ruby). It omits the coupling suite, semantic search,
  churn and blame. `CHANGELOG.md` has one line despite several releases.

## Plan

Five commits, ordered so each is independently verifiable and nothing depends on
a finding still open. Correctness of the answers comes before the performance
work, because the performance work is wasted on wrong answers.

### Commit 1 — reliability and release honesty *(done)*

C1, C3, C4, S2. Small, independent, each verifiable on its own.

- Share `is_reindexing` across HTTP sessions.
- Add `PRAGMA busy_timeout`.
- Add a timeout to every git subprocess and clamp the churn window.
- Build a real `lipo` universal macOS binary, or drop the artifact.

### Commit 2 — truthful results *(done)*

F1 (the cheap half) and F2. The highest-value change in the review: stop the
tools from asserting more than they know.

- `Database::resolve_symbol` with a deterministic preference order
  (production before tests and generated code, then path/line/id), replacing the
  bare `LIMIT 1`. `find_node_by_name` delegates to it.
- `Resolution { candidates, ambiguous, alternatives }` on every single-symbol
  result, rendered as a markdown warning naming the other definitions.
- `Page { total, shown, offset, limit, truncated }` on every list result, with a
  footer saying which `offset` gets the next page.
- `SymbolHint` — `file` / `qualified_name` — on the symbol request types, and
  `--file` / `--qualified-name` / `--limit` / `--offset` on both binaries via a
  shared `cli::tools::SymbolQuery`.
- `DISTINCT` + `ORDER BY` on the caller/callee queries: a caller that invoked
  the target three times previously filled three slots of the page and was
  counted three times.
- `analyze_impact` reports `truncated` when a node exceeds `IMPACT_FANOUT_CAP`,
  so a capped count reads as a lower bound.

The remaining half of F1 — import-scoped resolution, which would *reduce*
ambiguity rather than just report it — stays in commit 5.

**JSON shape change:** `count` on `CallList` / `UnusedResult` is replaced by
`total` + `shown` + `truncated`. `count` meant "how many we returned", which
read as "how many exist"; that ambiguity was the finding.

### Commit 3 — trustworthy index *(done)*

C6, O1, O2, O3, O4, F5.

- `index_meta` carrying schema version, extractor version, crate version and
  build time, stamped only once a build completes. `Staleness` distinguishes an
  unversioned index, a schema mismatch and an extractor mismatch — the last
  being the dangerous one, since those rows read fine and mean something else.
- Incremental indexing refuses a stale index (it cannot migrate rows it does
  not revisit); `symgraph index` detects this and rebuilds from scratch instead.
  Query paths warn on stderr so `--format json` on stdout stays parseable.
- Tool methods return `Result<String, String>`, so a failure reaches the client
  with `isError` set rather than as a successful result reading `"Error: …"`.
- `warn!` on each silent degradation: the FTS→LIKE search fallback, churn
  unavailable, and batch inserts dropping unmappable edges or refs.
- `Database::health` — staleness, provenance, FTS integrity, unresolved-ref
  count, and the share of names carried by more than one definition. Both
  `symgraph-status` and the CLI `status` report it. On symgraph itself that
  ambiguity figure is 11.5%, which is F1's blast radius as a number.
- Extraction records `parse_failed` when tree-sitter recovers from syntax
  errors, and `IndexConfig::max_file_bytes` (2 MiB default) skips files too
  large to be worth parsing. Both are counted and reported.

The parse-failure check immediately caught a real gap: `tree-sitter-groovy`
0.1.2 rejects an idiomatic `println new Calculator().add(1, 2)` as missing a
semicolon, so Groovy files parse partially. Symbol recovery is good enough that
the class and method still come out; the test now records this rather than
asserting a clean parse that was never happening.

### Commit 4 — supply chain and portability *(done)*

S1, S3, S4, S5, S6, F6, M3, M4, M5.

- `SHA256SUMS` generated over every release asset and verified by both
  installers before they unpack anything. Both also install `symgraph-cli`,
  which they previously discarded despite shipping it.
- The install script passes paths to Python as `sys.argv` rather than splicing
  them into the program text, and configures Claude Code through
  `claude mcp add --scope user` when the CLI is present — which sidesteps the
  question of which config file is authoritative, and keeps working if that
  changes. It falls back to `~/.claude.json`, not `~/.claude/settings.json`.
- `cargo deny` with a `deny.toml` covering advisories, licenses, sources and
  bans, wired into CI and `make check`.
- `rust-version = "1.90"` in `Cargo.toml` — computed from the dependency tree,
  where tree-sitter 0.27 sets the floor — with a CI job that builds against
  exactly that toolchain, reading the number from `Cargo.toml` so there is one
  source of truth. The README badge claimed 1.70.
- Release workflow permissions scoped per job; `contents: read` by default.
- Forward-slash path keys, normalized at the single point where paths enter
  the index and folded again on the way in from callers.
- Portable `make release` (BSD/GNU `sed` detected), and `make check` now covers
  the CLI-only combo and the supply-chain gate that CI gates on.
- The tag/`Cargo.toml` version check moved to a `preflight` job that gates
  every other job, instead of running after the release was published.
- README features rewritten (13 grammars, not 8; the coupling suite, semantic
  search, git integration and the honesty work were all unlisted), and a real
  CHANGELOG covering this work including its breaking JSON change.

**Found by the new gate:** `cargo deny` immediately flagged `chacha20 0.10.1`
as yanked, reached through `rmcp` → `rand`. Resolved by `cargo update -p
chacha20` to 0.10.2.

**Found while doing it — S9, still open.** `Cargo.lock` is in `.gitignore`.
symgraph ships binaries and installs them via `curl | bash`, so every CI and
release build resolves dependencies fresh: two builds of the same tag can embed
different transitive versions, and the `cargo deny` gate only ever checks
whatever resolved that day. It is also what let a yanked `chacha20` sit in the
tree unnoticed. The Cargo convention is to commit the lockfile for anything
that produces a binary — the crate can still publish to crates.io, where the
lockfile is ignored by consumers. This is a deliberate `.gitignore` entry, so
it is the author's call rather than something to change in passing.

**Not done:** SHA-pinning the GitHub Actions (part of S6). Resolving each
action's commit SHA needs network lookups that could not be verified here, and
inventing them would be worse than leaving the tags. The duplicate `build.yml`
(M2) is untracked local work — `ci.yml` now covers everything it did, including
its concurrency group, so it can be deleted, but that is the author's file to
remove.

### Commit 5 — scale *(done)*

F3, P1–P6, C2, C5, M1, plus the import-scoped half of F1.

- **Import-scoped resolution.** The resolution ladder gained a middle tier:
  same file, then a file the referencing file *imports from*, then the plain
  preference order. Import edges are themselves resolved references, so they
  are resolved in their own pass first and the scope they establish is then
  available to everything else. On symgraph's own index, call edges resolving
  to an arbitrary file fell from 698 to 469 — a third fewer guesses — with 285
  more now pointing at a file the caller actually imports.

  It does not shrink the module-graph SCC, which stays at 38 of 41 modules:
  a handful of remaining bad edges is enough to merge everything, so the tier
  breakdown is the honest measure and cycle membership remains approximate.
  It also cannot rescue an import that is itself ambiguous — pinned by a test
  that documents the limit rather than asserting a fix that is not there.

- **C5.** `RwLock<SyncDatabase>` → `Mutex<Database>`, which deletes the
  `unsafe impl Sync` outright. The crate now contains no `unsafe` at all. The
  old comment credited SQLite's serialized mode, but that protects the C
  library, not the `RefCell` statement cache two concurrent readers would race
  on.
- **C2.** Every tool method is `async` and runs its handler on
  `spawn_blocking`, so multi-second SQLite and `git` work no longer blocks a
  tokio worker — which over HTTP stalled every other session too.
- **F3.** `symgraph-context` asks the semantic index first and keeps the
  keyword walk as a fallback.
- **P1.** Indexing streams in chunks of 256 files. The walk now collects only
  metadata; contents are read, parsed and stored a chunk at a time, so peak
  memory is bounded by the chunk rather than by the repository.
- **P2.** A no-op incremental pass takes files whose size and mtime match the
  index as unchanged without reading or hashing them (`trust_file_stat`,
  on by default). The content hash still decides for anything whose stat
  differs.
- **P3.** `resolve_references` is one set-based `INSERT … SELECT` per phase
  instead of three or four queries per reference. Unresolvable references are
  now *kept* rather than deleted wholesale, which is what makes the
  unresolved-reference health figure mean anything.
- **P4.** `get_edge_endpoints` aggregates in SQL: 559 rows instead of 7246 on
  symgraph's index, lossless because the consumers count rather than inspect.
- **P5.** Reindexing named files no longer walks and hashes the whole tree.
- **P6.** `criterion` benches over full index, no-op incremental, and graph
  folding.
- **M1.** `tests/handlers_test.rs` covers the handler output surface the review
  found untested, in both markdown and JSON. Since both front-ends call these
  functions, it covers the CLI and the MCP server at once.

**Found by the new tests:** F8 above — `symgraph-implementations` has never
worked, for any language.

### Commit 7 — the parity the design doc claimed *(done)*

F4, plus the divergence the parity doc did not know it had.

- **F4.** `format` on all 14 request types; the five named in the finding plus
  `status` and `reindex`.
- **The parity collapse.** `search`, `context` and `status` had their own CLI
  implementations. Each drifted from its handler during this review — a fix
  applied to the handler did not reach the command a user runs, three separate
  times. They now call the same functions as the server, and
  `tests/cli_parity_test.rs` runs the real binary against the handler and
  compares the output, so "identical by construction" is checked rather than
  asserted. It also asserts every one of the 20 query commands emits valid JSON.
- CLI `reindex` gained `--files`, the targeted mode the parity table always
  listed, and its full-rebuild JSON now matches the tool's shape.
- `.claude/skills/symgraph-cli/SKILL.md`, the skill doc the parity design asked
  for — weighted towards reading the truncation and ambiguity signals, since an
  agent that treats `shown` as a total draws confident wrong conclusions.

**Found by the parity work — a bug this review introduced.** `delete_file`
dropped `nodes` before `unresolved_refs`, which holds a foreign key to it. That
was invisible for as long as resolution emptied `unresolved_refs` on every
pass; commit 5 started *keeping* unresolvable refs so the health figure could
mean something, and from then on every targeted reindex failed with "FOREIGN
KEY constraint failed" — reported only in a warnings field nothing asserted on.
Fixed by deleting refs first, and by matching them on `source_node_id` as well
as `file_path`, since a ref anchored to a node in this file may carry another
file's path. Two regression tests.

## Addendum — binary separation (2026-09-20)

Raised after the review closed: was `symgraph` / `symgraph-cli` paying its way?

Measured, it was not. The stated rationale — "builds without the server stack"
— produced a binary the same size either way (29 MB lean, 29 MB with
`--all-features`), because the linker already drops what a binary does not
reach. The 4 MB that is real only separates `symgraph` (33 MB) from a CLI-only
build, and every release tarball shipped *both* binaries, so users downloaded
62 MB to get a "lean" option they never chose.

Worse, they were not a superset and a subset but two divergent supersets:

| | `symgraph` | `symgraph-cli` |
|---|---|---|

The binary missing `reindex` and `watch` is the one in the MCPB bundle, the one
`install.sh` installs, and the one the MCP config points at.

They also shared 274 identical non-comment lines — 45% of one file, 70% of the
other — including six argument helpers defined twice. Only 7 of 24 shared
dispatch arms were still byte-identical. Commits 2, 4 and 7 of this review each
had to make the same edit in both files.

And the split was never needed for the lean build: the server dependency was
one `mod` declaration and one dispatch arm, both `#[cfg(feature = "server")]`-
gatable. One binary produces both artifacts.

**Resolved** by merging into a single `symgraph`, taking the CLI's richer
command surface and semantics, with `serve` cfg-gated. `src/main/server.rs`, a
stale unreferenced copy of `src/server.rs` predating the HTTP auth work, was
deleted at the same time.
